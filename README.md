# 比赛模型提交服务（Model Submission Service）

比赛组织方使用的单机 Web 提交服务：参赛队伍用浏览器把「**模型文件夹 + Docker 镜像**」
上传到服务器指定目录，服务端**实算每个文件的 SHA256** 并给出可核对的校验码。
面向"参赛队伍多、单队数据量大（几十 GB）、参赛者网络环境参差不齐"的真实比赛场景，
提供大文件并行上传、断点续传、速度/预计剩余时间显示和组织者管理后台。

## 解决什么问题

参赛者分布各地、上传动辄几十 GB，组织方需要一条"**随时随地能传 + 传完可验证 + 断了不重来**"的通道：

| 痛点 | 本服务的做法 |
|---|---|
| 大文件传一半断了，重传要几小时 | 分片上传 + **断点续传**：断网/关页面/超时后重进页面点「继续」，从断点接着传，已传数据不丢弃 |
| 慢线路（如国际隧道）单请求超时 | **分片大小自适应**（256KB–16MB，按实测速率调整，目标 25 秒/片）；超时自动缩片重试 |
| 文件夹里几十个文件，一个个传太慢 | **文件级全并行上传**（不设并发上限），页面显示总速度 + 预计剩余时间 |
| 传完了怎么证明没传坏 | 服务端实算 SHA256，返回 `sha256sum -c` 格式校验码，参赛者本地一行命令核对 |
| 组织者要知道各队进度/出错原因 | 管理后台：各队大小/状态/文件数/完成时间，**客户端报错上报**可见，可删除队伍 |
| 参赛者不会搭环境 | 只需"链接 + 口令"，浏览器直接操作；PC 选文件夹、手机可多次「添加文件」累加 |

## 功能清单

- **上传**：文件夹/多文件并行上传；单文件 ≤100GB、单队 ≤200GB；`>1GB` 文件免浏览器预哈希；
  断点续传（含服务端 offset 漂移 409 重同步）、失败自动重试（最多 2 轮）+ 手动「重试该文件」
- **校验**：服务端逐文件实算 SHA256，完成提交后列出全部校验码（一键复制，`sha256sum -c` 格式）
- **镜像**：可选上传 `docker save` 出的 tar（与模型文件同一套断点续传通道）
- **管理**：组织者后台口令登录，查看队伍列表/磁盘剩余/客户端报错，删除队伍
- **线路**：多入口进度共享，可中途切换（直连主线路 + Cloudflare 隧道备用，见下）

## 架构

- **服务端**：Flask 单文件应用（`.service/app.py`，约 640 行），生产环境由
  `waitress-serve`（128 线程）加载，端口 8080
- **前端**：单页 `.service/static/index.html`，无构建步骤——纯 JS 流式 SHA256、
  并行上传、速度采样（30s 窗口）、文件篮式选择入口，全部内联
- **状态**：会话状态内存 + `.service/state/sessions.json` 双写（每秒/关键节点落盘），
  重启不丢进度
- **公网入口**（三条线路，同一后端，进度共享）：
  1. **国内直连（主）**：`http://<服务器公网IP>/` —— 公网 80 端口经云 NAT 落到入口机，
     由纯 TCP 转发服务（`docs/systemd-units/relay-port80.py`，每连接一线程）转到后端 8080；
     实测链路带宽 ~22MB/s，无 100s 超时限制
  2. **Cloudflare 快速隧道（备用）**：地址随隧道重启变化；有 100s 源站超时，
     慢线路会 524（无害，前端自动续传）
  3. **SSH 反向隧道（休眠备用）**：`公网IP:8080`，当前云 NAT 未放行 8080，日后放行即自动可用
- **部署**：systemd 管理（4 个 unit：本机 3 个 + 入口机 1 个，备份见 `docs/systemd-units/`）

## 快速开始（本地）

```bash
# 1. 依赖（仅需 flask + waitress）
python3 -m venv .service/venv
.service/venv/bin/pip install flask waitress

# 2. 运行（首次启动自动生成 .service/tokens.json 双口令，权限 0600，不打印）
cd .service
../.service/venv/bin/waitress-serve --listen=0.0.0.0:8080 --threads=128 --channel-timeout=600 app:app
# 开发调试也可：.service/venv/bin/python app.py（Flask 开发服务器，断连语义与 waitress 略有差异）
# 3. 从 tokens.json 取出 submit/admin 口令分发给参赛者与组织者（该文件不入库、勿外传）

# 4. 浏览器打开 http://127.0.0.1:8080/，输入口令即可使用
```

生产部署细节（systemd unit、端口转发、Cloudflare 隧道、限额参数）见
`docs/项目说明.md` 与 `docs/systemd-units/`。

## 安全模型（改动时勿破坏）

- **双口令**：提交口令（参赛者）/ 后台口令（组织者），HMAC 签名 cookie；
  提交口令无法按队名查询其他队伍
- **路径强校验**：队名/相对路径清洗 + realpath 兜底，文件只能落在 `<队名>/` 目录内
- **限流**：3600 req/min/真实客户端 IP（经隧道时解析 CF-Connecting-IP）
- **限额与磁盘保护**：单请求 16MB / 单文件 100GB / 单队 200GB；磁盘剩余 <5GB 拒绝写入
- **密钥不入库**：`.gitignore` 全排除+白名单，`tokens.json`/会话状态/队伍数据一律不提交
